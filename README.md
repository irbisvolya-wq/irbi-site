# IRBI — сайт і робочі кабінети

Вебсервіс клінінгу в Чернігові. Публічна частина працює в режимі підготовки до запуску. Клієнт надсилає запит; координатор окремо погоджує дату, тривалість і вартість.

## Склад проєкту

- `index.html`, `app.js`: послуги, прайс, калькулятор і форма інтересу;
- `portal.html`, `portal.js`: вхід, відновлення пароля, кабінети за ролями, координація, графік, чек-листи й фото;
- `booking.*`, `customer.js`: запити, повторне замовлення, профіль і листування клієнта;
- `messages.*`, `notifications.js`: листування координатора та сповіщення клієнта;
- `inventory.*`: матеріали, закупівлі й списання;
- `staff.*`, `earnings.*`: персонал, адміністративні нарахування й перегляд клінером власних виплат;
- `finance.*`, `payments.*`: витрати, звіти й облік фактично отриманих оплат;
- `supabase/patches`: зміни серверної частини; `supabase/tests`: транзакційні перевірки з відкатом.

Frontend — статичні HTML та ES-модулі. Backend — Supabase Auth/Postgres/Storage і RPC. Публічний ключ у frontend не є секретом; доступ до даних забезпечують серверні дозволи, RLS і перевірки ролей.

## Перевірка і випуск

Див. [LAUNCH_READINESS.md](LAUNCH_READINESS.md): перевірені сценарії, вже застосовані серверні зміни та відкриті умови запуску. Поточна публікація — GitHub Pages із main. Vercel не є поточним хостингом. Детальний [архітектурний аудит](docs/ARCHITECTURE_AUDIT_2026-11-25.md) описує перевірений контур і залишкові задачі.

```sh
node --test tests/*.cjs tests/*.mjs
for source in *.js; do node --check "$source" || exit 1; done
git diff --check
```

У supabase/functions збережені вихідні коди трьох діючих Edge Functions; supabase/config.toml фіксує поточні verify_jwt. Репозиторій ще не містить повної відтворюваної схеми Supabase. Окремі SQL patches не замінюють резервну копію чи повне відтворення сервера. Не застосовуйте повторно вже виконані patches без перевірки історії міграцій.
