# Рабочая очередь координатора

Страница: /attention.html. Доступ: admin и dispatcher. В рабочем кабинете добавлена кнопка «Потребує уваги».

Показывает четыре категории:

- все заявки pending, включая прошедшие желаемые даты;
- confirmed без assigned_cleaner_id;
- assigned/accepted/en_route/arrived с прошедшим временем начала и in_progress с прошедшим плановым завершением;
- инциденты open/in_review/resolved, до перехода в closed.

Инциденты безопасности выше остальных задач. Просроченные заявки и работы выделены; будущие работы не считаются задержанными. Неизвестное время завершения не заменяется выдуманной длительностью.

Запросы пагинируются по 500 строк с устойчивым порядком. Счётчики не ограничены последними 50 заказами. Ошибка любой страницы отклоняет весь снимок: вместо частичных итогов или ложного нуля показывается сообщение о недоступности полной очереди.

Очередь обновляется каждые 60 секунд только при открытой видимой странице; есть ручное обновление. При смене сессии содержимое очищается, запоздавший ответ не восстанавливает прежние данные.

Ссылка открывает конкретный заказ через /portal.html?order=UUID. Фильтр добавляется к существующим ограничениям клиента/клинера и не обходит RLS. Для инцидентов view=issues раскрывает раздел инцидентов выбранного заказа. Доступен возврат ко всем заказам.

Используются существующие SELECT-права и RLS. Новых разрешений и серверных записей нет. Страница не отправляет email, SMS, push или сообщения в мессенджеры. Доставка уведомлений координатору за пределами открытой страницы и обработка prelaunch-обращений остаются отдельными задачами.

Проверки: tests/attention-data.mjs, tests/attention-ui.cjs, дополненные tests/order-list.mjs. Весь набор node --test tests/*.cjs tests/*.mjs: 60 успешных результатов, 0 ошибок. Синтаксис JS и локальные ссылки проверены.
